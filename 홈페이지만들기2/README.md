# 부산한일라이온스 홈페이지

남색·금색의 반응형 홈페이지. 메인 화면을 홈(날씨·뉴스), 봉사활동, 행사사진, 동호회 일정 및 사진의 네 영역으로 구성했습니다. 50~60대 이용자가 읽기 편하도록 본문 19px, 큰 버튼, 높은 명암 대비를 적용했습니다. 회원 소개, 창립 역사, 회원사, 경조사, 골프회·산악회 일정, 355-A 부산지구 동정, 복지·봉사 통계, Google Scholar 검색과 YouTube 검색 연결을 포함합니다.

## Windows 바탕화면에 설치

1. ZIP을 다운로드합니다. 다운로드한 파일을 오른쪽 클릭 → **모두 압축 풀기**.
2. 압축을 푼 `홈페이지만들기2` 폴더를 바탕화면으로 옮깁니다. 폴더 안에 `index.html`이 있는지 확인하세요.
3. `홈페이지 열기.cmd` 또는 `index.html`을 더블 클릭하면 기본 화면이 열립니다.
4. 저장 뉴스·공개 사진 JSON·통계 CSV는 브라우저 보안 정책상 파일 더블 클릭 방식에서 로드되지 않을 수 있습니다. 모든 기능은 GitHub Pages 또는 로컬 HTTP 서버로 확인하세요. Python 3가 설치되어 있다면 이 폴더에서 `python -m http.server 8000`을 실행하고 브라우저에서 `http://localhost:8000`을 여세요.

이 작업은 클라우드의 `/workspace/Desktop/홈페이지만들기2`에 파일을 만들었습니다. 사용자의 실제 Windows 바탕화면에는 자동으로 복사되지 않습니다.

## GitHub 업로드 및 매일 갱신

1. `index.html`, `styles.css`, `dashboard.js`, `bootstrap.js`, `admin.js`, `data.js`, `assets`, `data`, `scripts`, `.github`, `.nojekyll`을 저장소 루트에 올립니다. 폴더 자체를 한 단계 더 감싸지 마세요. `.github/workflows/daily-pages.yml`이 누락되지 않게 확인하세요.
2. 저장소의 Settings → Pages → Source를 **GitHub Actions**로 설정합니다. main 브랜치를 사용합니다. 다른 브랜치를 쓰면 workflow의 push.branches를 수정하세요.
3. Actions → **Daily data and GitHub Pages** → Run workflow로 실행합니다. Actions 사용이 허용되어 있어야 하며, 계정·저장소 정책에 따라 Pages 사용 가능 여부가 다릅니다.
4. 매일 한국시간 오전 6시 예약으로 날씨·뉴스를 수집하고 사이트를 다시 배포합니다. GitHub 예약 실행은 지연 또는 비활성화될 수 있습니다. 실제 운영에서는 Actions 실행 기록을 확인하세요.
5. 데이터 캐시는 배포 결과에 포함되며 main 브랜치에 자동 커밋하지 않습니다. 뉴스·날씨 수집 실패 시 확인되지 않은 신규 값으로 바꾸지 않습니다. 화면의 마지막 수집 시각과 실행 로그를 확인하세요. 첫 수집 전에는 실제 데이터가 없습니다.

GitHub 업로드와 게시를 대신 수행하지 않았습니다. 현재 검증은 클라우드에서 진행했으며 GitHub Actions 배포는 업로드 후 확인해야 합니다.

## 사진 업데이트

홈의 행사사진 영역 → **사진 업데이트**를 펼칩니다. 제목·날짜를 입력하고 PNG/JPEG/WebP 사진을 선택하면 바로 표시되고 해당 브라우저의 IndexedDB에 저장됩니다. 파일당 최대 10MB, 최대 30장입니다. 삭제도 같은 브라우저에서만 적용됩니다. 브라우저 저장소를 지우면 로컬 편집은 사라집니다.

공개하려면 **사진 업데이트 파일 다운로드**를 누르고, 내려받은 `gallery.json`으로 GitHub의 `data/gallery.json`을 교체하세요. 다시 배포되면 방문자에게 반영됩니다. 로그인·서버 저장 기능이 없으므로 방문자의 사진 선택이 사이트 전체에 자동 게시되지는 않습니다. 공개할 사진만 등록하세요. 큰 사진은 미리 용량을 줄이는 편이 좋습니다.

수동 방식: 사진 파일을 assets 폴더에 추가하고 data.js의 photos 배열에 `{image:'assets/photo.jpg',title:'행사명',date:'2026-10-08'}`를 넣어도 됩니다. 실제 행사사진이 첨부되지 않아 초기 화면은 부산관광공사의 광안대교 사진만 사용했습니다. 공식 클럽 행사로 표시하지 않았습니다.

## 회원·회원사·동호회 자료

`data.js` 배열에 확인된 실제 자료를 넣습니다. 각 배열 옆의 형식을 참고하세요. 회원·경조사·사진은 공개 동의를 확인하세요. 빈 배열은 자료 준비 안내를 표시합니다. 관리자 편집 화면이나 data.js로 공식 유튜브 주소가 생기면 youtube에 `{title:'공식 채널',url:'https://www.youtube.com/@실제채널'}`을 등록하세요. 현재는 검증되지 않은 채널을 추천하는 대신 봉사 관련 검색 링크를 제공합니다.

## 날씨

기본 기간은 요청한 **2026년 10월 1일~8일**입니다. 날짜를 변경해 다른 기간도 조회할 수 있습니다(최대 32일). 부산·서울·대구를 선택하면 실제 Open-Meteo 자료의 최저·최고기온을 그래프와 표로 표시합니다. 선택 기간에 오늘·어제가 포함되면 요약 카드도 채워집니다. 오늘은 한국시간 기준 파란색입니다. 과거 기간은 archive API를 사용합니다. 오래된 기간을 선택했을 때 오늘 카드에는 자료 없음이 표시됩니다.

Open-Meteo의 모델 기반 자료이며 기상청 관측값이나 AccuWeather 값으로 표시하지 않습니다. API 접속이 차단되면 날짜가 일치하는 저장 자료를 사용하거나 실패 안내를 표시합니다. 임의 기온을 넣지 않았습니다. 기상청 날씨누리의 공식 확인 링크도 제공합니다. AccuWeather·기상청 API는 별도 키·이용조건 검토가 필요해 연결하지 않았습니다.

## 복지 및 봉사 통계

`data/statistics.csv`에 공식 기관에서 확인한 수치와 출처를 입력하면 그래프가 표시됩니다. 현재 실제 수치는 미등록입니다. CSV 파일 입력은 브라우저 미리 보기이고 공개 저장은 파일을 GitHub에 교체하는 방식입니다.

열: `metric,year,region,value,unit,source_name,source_url`

metric은 `budget`(복지예산), `recipients`(수급자), `regional`(지역 현황), `volunteering1365`, `volunteeringVms` 중 하나입니다. 단위와 수치의 집계 정의를 통일하세요. source_url에는 해당 **자료 상세 페이지의 HTTPS 주소**를 넣으세요. 동일 지표·지역·연도 중복 및 단위 혼합은 그래프를 표시하지 않습니다. 지표별로 확보한 최신 연도 기준 10년을 표시하며, 10개 연도가 없으면 확보된 데이터만 표시합니다. 지역별 현황은 지역 선택 후 연도 추이 방식입니다.

지표 정의와 숫자를 자동 추정하지 않습니다. 복지통계는 안정적인 API·공식 자료 파일 확인 없이 매일 변경하지 않으며 사용자 입력 자료를 사용합니다. 1365와 VMS는 중복 가능성이 있어 단순 합산하지 않습니다.

## 개발 및 확인

추가 패키지 설치·빌드가 필요 없습니다. Python 3.12 이상으로 `python scripts/update_data.py`를 실행하면 데이터 수집을 시도합니다. 외부 네트워크로 api.open-meteo.com, archive-api.open-meteo.com, news.google.com 접속이 필요합니다. 비밀 키는 사용하지 않습니다. `node --check dashboard.js`로 구문 확인이 가능합니다.

클라우드에서 화면 네 영역, 모바일 메뉴, 사진 업로드·재시작 후 저장·내려받기·삭제, CSV 그래프와 출처 표, 도시 선택, 기온 그래프와 오늘 강조(검증용 데이터), API 실패 안내를 확인했습니다. 검증용 데이터는 배포 파일에 넣지 않았습니다. 부산·서울·대구의 2026-10-01~08 Open-Meteo 실제 응답을 수집하여 저장했습니다. 2026-10-08 한국시간에 부산일보 기사 5건을 수집했습니다. 복지 10년 통계의 실제 수치는 아직 확보하지 않았습니다.

## 동호회 일정 사진 업데이트

동호회 일정 아래 **동호회 일정·사진 업데이트**를 펼치고 새 일정 또는 기존 일정을 선택하세요. 골프회·산악회, 제목, 날짜, 장소, 안내와 사진을 입력하고 **일정과 사진 저장**을 누르면 브라우저에 보관됩니다. 한 일정당 사진 20장, 파일당 10MB 이하 PNG/JPEG/WebP를 지원합니다. 일정 카드와 상세 창에서 사진을 볼 수 있고 개별 사진을 삭제할 수 있습니다.

공개 반영은 **동호회 업데이트 파일 다운로드**로 받은 clubs.json을 GitHub의 `홈페이지만들기2/data/clubs.json`에 올려 교체하세요. 홈페이지 파일이 저장소 루트에 있다면 `data/clubs.json`을 교체합니다. 재배포 후 방문자에게 표시됩니다. 브라우저 편집 자체는 다른 방문자에게 자동으로 공개되지 않습니다. data/clubs.json이 있으면 전체 공개 일정 목록을 그 파일에서 읽습니다. 수동으로 data.js에 입력할 경우 images 배열에 assets 경로를 넣을 수 있습니다.

## 관리자 편집 (파일 내려받기 방식)

상단 **관리자** 또는 페이지 하단 **관리자 설정**에서 아이디 `login`, 비밀번호 `1234`로 로컬 편집 화면을 엽니다. 이 비밀번호는 정적 파일에서 확인할 수 있는 편집 화면 잠금이며 실제 인증·공개 수정 권한 보장이 아닙니다. 사용자가 선택한 방식은 파일 다운로드 후 GitHub 반영입니다. GitHub 저장소의 collaborator 권한으로 실제 공개 변경 담당자를 지정하세요. 브라우저 비밀번호를 GitHub 계정 비밀번호로 쓰지 마세요.

기본 설정에서 홈페이지 이름, 소개, 편집 담당자 이름, 공식 로고, 뉴스 제목·검색 주제·표시 방식, 날씨 도시·기간, 각 영역 공개 여부를 설정합니다. 내용 편집에서 회원, 연혁, 회원사, 경조사, 봉사활동(분류에 지구를 넣으면 지구 봉사로 표시), 부산지구 동정, 동호회, 행사사진, 유튜브 채널, 수동 뉴스 항목과 사진을 관리할 수 있습니다. 봉사 사진은 활동별 최대 20장, 사진당 10MB 이하입니다. CSV 통계도 관리자 로그인 후 가져오면 로컬 설정에 보관됩니다.

수정 후 **전체 업데이트 파일 다운로드**를 눌러 `content.json`을 받으세요. GitHub에 있는 `홈페이지만들기2/data/content.json`을 이 파일로 교체합니다. 홈페이지가 저장소 루트에 있다면 `data/content.json`을 교체합니다. 재배포 후 방문자에게 적용됩니다. 기존 업데이트 파일을 가져와 다른 PC에서도 편집할 수 있습니다. 초기화는 현재 브라우저에 저장한 편집만 지웁니다. 로그아웃해도 저장된 미리보기 자료는 현재 브라우저에 남습니다.

전체 업데이트 파일은 settings, clubData, 선택적 headlines/statistics_csv를 담습니다. 이 파일의 내용이 기본 data.js·clubs.json·gallery.json보다 우선하며, 브라우저에 저장된 로컬 편집이 있으면 그것이 공개 파일보다 우선합니다. 최신 공개 내용을 보려면 관리자에서 브라우저 설정을 초기화하거나 새 브라우저를 사용하세요.

뉴스 표시 방식의 **매일 수집한 최신 뉴스**는 수집 파일을, **관리자가 선택한 기사**는 수동 뉴스 목록을 사용합니다. 수동 편집 목록은 자동 뉴스 파일로 덮어쓰지 않습니다. 기사 원문과 제목만 연결합니다. 주제별 그래프는 수집·선택된 제목의 키워드별 기사 건수이며 사회복지 실적이나 의학적 효과가 아닙니다. 각 기사 매체와 날짜, 수집 시각 또는 관리자 편집 시각을 표시합니다.

자동 갱신은 GitHub Actions 설정 후 작동합니다. 홈페이지 파일을 main 저장소 루트에 올리고 `.github/workflows/daily-pages.yml`도 저장소 루트 경로에 올려 주세요. Settings → Pages → Source를 **GitHub Actions**로 바꾸고 workflow를 처음 실행하세요. 예약 실행은 기본 브랜치에 워크플로 파일이 있어야 합니다. 현재 다운로드용 브랜치의 폴더 안에 있는 `.github`만으로는 예약 실행이 시작되지 않습니다. workflow는 저장소 루트 또는 홈페이지만들기2 하위 폴더를 자동으로 인식합니다. 예약은 한국시간 오전 6시이며 GitHub 사정으로 지연될 수 있습니다. 웹 공개 및 예약 실행은 사용자 설정 후 확인해야 합니다.
